Mission 2 Reflection
1. Which cloud infrastructure component do you think is the most important? Why?
I believe that networking is the most critical component because it dictates how we interact with every other resource. During this lab, my initial struggles with Git authentication and IP addresses showed me that even if the compute and storage are ready, nothing works if the connection is broken. Networking provides the essential bridge that allows cloud engineers to reach, manage, and secure their infrastructure from anywhere in the world.
2. How does Linux support cloud computing?
Linux supports cloud computing by providing a powerful, stable environment where everything is managed through a command-line interface. I learned that in the cloud, we don't just "run" files like applications; we must use specific Linux tools like nano to edit or cat to view them. This lightweight and command-driven nature makes Linux the perfect choice for managing thousands of virtual servers efficiently and automatically.
3. Why is technical documentation important before deploying infrastructure?
Technical documentation is vital because it prevents the mess and confusion that comes from disorganized files and duplicate resources. In this activity, I realized that without a clear documentation plan, it is easy to save files in the wrong directory or create duplicates that clutter the repository. Having a pre-deployment report ensures the whole team understands the architecture and follows the same naming and folder standards.
4. What new skills did you learn during this laboratory activity?
I learned how to use terminal commands like lscpu and lsblk to audit a server’s hardware and how to troubleshoot common Git errors like "Author Identity Unknown." I also gained the skill of moving and cleaning up files using the mv and rm commands, which helped me fix my initial organizational mistakes. Most importantly, I learned how to "pull" external work, like my Canva diagram, back into a CLI environment to keep everything synchronized.
5. How has your GitHub portfolio improved after completing this mission?
My GitHub portfolio has improved from a simple collection of files into a professional, structured cloud repository. Initially, I had files scattered in the root directory, but after reflecting on my mistakes, I learned to organize everything within a dedicated project folder. It now serves as a clear record of my ability to investigate a system, design an architecture, and maintain professional-grade documentation through the terminal.
